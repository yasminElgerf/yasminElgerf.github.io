Reading Responses

Reading Response 1 — The Garden of Forking Paths

Borges's story made me think about how time does not always have to be imagined as one straight line. The idea that different choices can create different possible futures reminded me of Git branching, because each branch can hold a different version of the same project.

I also found the idea of the labyrinth interesting because it was not just a physical maze. It was more about time, decisions, and possibilities. That connects to coding because websites and programs can also have different paths depending on what the user clicks changes, or chooses.

This reading helped me see confusion in a more creative way. A project does not always need to move in one clear, perfect direction. Sometimes branching, contradictions, and multiple outcomes can become part of the structure of the work itself.

Reading Response 2 — Glitch Studies Manifesto

This manifesto changed how I think about mistakes in digital work. Instead of treating glitches only as things that need to be fixed, Menkman presents them as moments that can reveal the hidden systems behind media and technology.

That connects to coding because errors often show us what is really happening underneath the surface. Sometimes a broken layout, distorted image, or unexpected result can be more interesting than the clean version I originally planned. It made me think about how “bad” design can still have meaning if it makes the viewer notice the system.

My main takeaway is that technology is not as perfect or invisible as it pretends to be Glitches interrupt the normal experience and make us pay attention to the tools, code, and structures that usually stay hidden.

Reading Response 3 — The Aesthetic of Failure

This reading made me think about failure in a different way. Michele White explains that some net artists use broken-looking code, fake errors, confusing interfaces, and glitches on purpose. Instead of making the internet feel smooth and easy to use, these artists make the viewer notice the system behind the screen.

I connected this to our coding work because most of the time we are trying to fix errors and make everything function properly. This reading challenged that idea by showing that “wrong” code or a frustrating interface can still have meaning. A glitch can reveal how a system works instead of hiding the technical parts.

What surprised me was how a confusing website can make the user feel less in control Usually, interactivity is supposed to make the user feel powerful, but these artworks interrupt that feeling. My main takeaway is that failure can be an aesthetic choice, but it can also lose its power if glitches become too familiar or trendy.

Reading Response 4 — Software & Art

Casey Reas's reading stood out to me because he describes programming as something that can be fluid and intuitive, almost like drawing. I liked the idea that code does not always have to feel completely technical or strict. It can be reshaped, tested, changed, and reused to create many different variations.

The connection to Sol LeWitt's wall drawings helped me understand code as a set of instructions. LeWitt's work begins as a written plan that someone else interprets, and Reas compares that to software structures. This made me think about how the same idea can lead to different final results depending on who implements it or what tools are used.

A key takeaway for me is that programming languages can be seen like artistic materials. Processing, Flash, and C++ all shape the final work differently, just like paint, paper, or clay would. This reading made me imagine writing instructions for a visual piece and then seeing how different people or programs would interpret the same structure.

Reading Response 5 — Introduction to net.art

I found this reading interesting because it presents net.art as more than just art placed on the internet. It describes net.art as a playful and independent way of working that values communication, collaboration, immediacy, and experimentation. The internet becomes the place where the work is made, shared, discussed, and critiqued all at once.

This connects to our GitHub pages because publishing a webpage means putting work into a public network. It is not just a private file anymore. The reading made me think about how websites can be used for more than clean presentation. They can also be used for performance, identity, disruption, humour, or small interventions.

One thing that challenged me was the tension between being independent and becoming recognized by institutions. The text celebrates working outside museums and galleries, but it also explains how net.art eventually became absorbed by those same systems. My takeaway is that net.art feels like an attitude as much as an art form: it is experimental, ironic, temporary, and willing to misuse the internet creatively.
